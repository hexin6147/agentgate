## 1. 先看分层：机制通了，管理没通

> 按 FR 逐条打勾，会得到 **✅ 2 / 🟡 13 / ❌ 3**，读起来像"什么都只做了一半"。
> 这个印象是失真的。真实情况是：**机制层跑通了，配置层和管理层没通。**

### 1.1 五层

| 层 | 内容 | 状态 | 典型证据 |
|---|---|---|---|
| **机制层** | 接入、执行、trace、判定、回归 | ✅ 通 | 七步闭环走通；规则版 held-out 60% → LLM 100% |
| **配置层** | 围栏可配、Evaluator 可配、接入不改平台代码 | ❌ | `tools.py` 围栏硬编码；`factory.py` 用 `if/else` 注册 |
| **管理层** | 注册、版本、CaseSet、冻结、权限 | ❌ | 用目录当用例集；`metadata.version` 只是字符串 |
| **资源层** | token、延迟、成本 | ❌ | `LLMClient.chat` 丢弃 `response.usage` |
| **产品层** | 工作台 UI、多租户、协作 | ❌ | 只有 CLI + 飞书 |

### 1.2 四个缺口各自停在哪一层

| 缺口 | 机制层 | 管理层 / 配置层 |
|---|---|---|
| P1 管控规则不可配置 | ✅ 围栏 F1–F5 / T1/T2/T5、人工确认已实现 | ❌ 围栏写死在代码里 |
| P2 过程不可观测 | ✅ 节点级 trace，完整率 100% | ❌ 无超时、重试、显式状态机 |
| P3 结果不可回归 | ✅ 批量运行、指标聚合、版本对比 | ❌ 无 CaseSet 版本与冻结 |
| P4 评测不可复用 | ✅ Adapter + 两类范式 | ❌ 无注册机制，接新 Agent 要改平台 |

> 四个缺口都是**"机制成立、管理层缺失"**，不是"方向错了"。

### 1.3 哪些本来就不是平台的事

| 不是平台的职责 | 归属 |
|---|---|
| 多步任务编排（planning） | Agent 自己 |
| 模型能力提升 | 模型 / 算法 |
| 业务 SOP 与红线内容 | 业务方 |
| 组织责任与上线签字流程 | 组织 |
| 线上流量、多租户、容器隔离、真实系统集成 | PRD 明确 Out of Scope |

**但有一条例外**：

> **"长任务的评测"是平台的事**——步级成功率、任务完成率、恢复率。
> 当前只有单轮用例、单次工具调用，所以这一层是空的。**这是缺口，不是边界。**

### 1.4 一句话

> 平台交付的是**"机制成立"**，不是**"产品完整"**。
> 判断标准不是功能列表长度，而是一条评测闭环能不能走通：
> `接入 → 批量跑 → 看 trace → 归因 → 修 → 回归 → 门禁判定`
> 这七步走通了，包括它自己打脸的那一步（规则版 held-out 只有 60%）。

## 5. 结论：现在到底是什么

### 5.1 已完成的"引擎"

- Agent Adapter（Python）
- Harness 基础（run_id、异常隔离、trace）
- LangGraph 编排
- Mock 工具 + F/T 围栏
- B1–B6 / R1–R6 规则
- LLM 意图分类 + 摘要 + 护栏
- BGE 语义筛选
- LLM-as-judge
- 飞书 @ / 回复 / 卡片 / 回调
- 评测打分、聚合、回归对比
- Rubric 加载/校验/加权/硬门槛
- Sample A（规则 + LLM）与 Sample B（规则）
- 127 个测试

### 5.2 尚未完成的"平台外壳"

- Agent 注册表 / 版本 / 持久化
- CaseSet / 用例导入 CLI
- 成本统计
- Markdown 报告
- Trace viewer
- Streamlit 工作台
- 确认超时 / 事件幂等
- Harness timeout/retry

### 5.3 准确的一句话

> **当前是一个"评测引擎 + 脚本 + 飞书 Bot"，不是一个完整体验的平台产品。**
> 更准确的分层说法见 §1：机制层通了，配置层、管理层、资源层没通。
> 引擎、评测闭环和 Rubric 加权是真的；平台外壳（注册、持久化、CaseSet、UI）大部分还没做。
> 完整的「瓶颈 → 痛点 → 缺口 → 模块 → FR → 代码 → 测试 → 指标」链路见 `16-全链路映射.md`。
