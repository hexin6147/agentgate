## 2. 接口契约

### 2.1 `logging.py`（新增）

```python
def set_trace(trace_id: str, run_id: str | None = None) -> None
def log_event(event: str, level: str = "info", **fields) -> None
```

- 用 `contextvars.ContextVar` 存 `trace_id/run_id/span_id`；
- 输出 `logs/agentgate.jsonl`，一行一个 JSON；
- 必填字段：`ts, level, event, trace_id, run_id`；可选：`span_id, step, latency_ms, error_type, msg`；
- `error_type` 枚举：`timeout | validation | upstream | internal`。

### 2.2 `trace.py`（追加，不改旧接口）

```python
class TraceRecorder:
    def start_span(self, name: str, parent_id: str | None = None, **attrs) -> str
    def end_span(self, span_id: str, status: str = "ok", **attrs) -> None
    @property
    def spans(self) -> list[dict]
```

- span 字段：`span_id, parent_id, name, start_ts, end_ts, status, attrs`；
- `record()` 保持原样，旧测试不许挂；
- 根 span 在 `harness.run_case` 里建：`name="run"`；
- 深度由 parent 链计算，P0 要求 ≥3 层（run → step → tool/llm）。

### 2.3 `store.py`（新增）

SQLite：`data/agentgate.db`（路径可用 `AGENTGATE_DB` 覆盖）。

```sql
CREATE TABLE runs (
  run_id TEXT PRIMARY KEY, trace_id TEXT NOT NULL, case_id TEXT NOT NULL,
  scenario TEXT, status TEXT, route TEXT, output TEXT, error TEXT,
  started_at TEXT, ended_at TEXT
);
CREATE INDEX idx_runs_trace ON runs(trace_id);
CREATE INDEX idx_runs_scenario ON runs(scenario);

CREATE TABLE spans (
  span_id TEXT PRIMARY KEY, run_id TEXT NOT NULL, parent_id TEXT,
  name TEXT NOT NULL, start_ts TEXT, end_ts TEXT, status TEXT, attrs_json TEXT
);
CREATE INDEX idx_spans_run ON spans(run_id);

CREATE TABLE usage (
  id INTEGER PRIMARY KEY AUTOINCREMENT, run_id TEXT, span_id TEXT,
  model TEXT, prompt_tokens INTEGER, completion_tokens INTEGER,
  latency_ms REAL, created_at TEXT
);

CREATE TABLE reports (
  report_id TEXT PRIMARY KEY, run_id TEXT, scenario TEXT,
  metrics_json TEXT, created_at TEXT
);
```

```python
def init_db() -> None
def save_run(run: RunResult, scenario: str | None = None) -> None
def save_spans(run_id: str, spans: list[dict]) -> None
def save_usage(rows: list[dict]) -> None
def save_report(report: dict, run_id: str | None = None) -> None
def get_run(run_id: str) -> dict | None
def get_spans(run_id: str) -> list[dict]
def query_runs(scenario: str | None = None, trace_id: str | None = None, limit: int = 50) -> list[dict]
```

- `trace_id` 先等于 `run_id`，但两列都留，方便以后拆；
- 只允许 `sqlite3` + 标准库。

### 2.4 `usage.py`（新增）+ `llm.py`（改）

```python
@contextmanager
def collect_usage() -> Iterator[list[dict]]
def record_usage(model: str, prompt_tokens: int, completion_tokens: int, latency_ms: float) -> None
```

- `LLMClient.chat` 里：计时 → 调 API → `usage = getattr(response, "usage", None)` → 有就 `record_usage(...)`；
- **签名不变**，调用方不改；
- Ollama 不返回 usage 时，token 记 0，但 latency 必须记。

## 8. P0 计划补充（2026-11-21，实施前确认）

> **触发原因**：§4 第 1 条要求跑 3 个 case，第 5 条要求 `usage` 表有记录；但 §0/§1 的单 case 路径是 `RuleBasedAgent`（纯规则，不调 LLM），按字面执行 `usage` 必然为空。这是计划 GAP，补充如下。**§2 的接口契约不变。**

### 8.1 usage 的产生路径

- P0 验收的 3 个 case 走 `factory.build_agent("llm", context="rule")`（现成的 LangGraphAgent + LLM 分类器/摘要器），不是纯 rule agent；**不重写 `RuleBasedAgent`**，其契约和现有测试保持不变。
- 每次 case 至少产生一次真实 Ollama 调用；`LLMClient.chat` 记录 prompt/completion/latency，`harness` 通过 `collect_usage()` 落到 `usage` 表。
- 不用假 token / fake OpenAI client 冒充 usage；Ollama 不返回 usage 时 token 记 0，但 latency 必须记录。
- `pytest` 里的确定性测试仍用 rule agent / fake chat_fn，不依赖 Ollama。

### 8.2 scenario 传递

- `Harness.__init__` / `Harness.run_case` / `Runner.run_case_file` 增加可选 `scenario` 参数，默认 `None`；`save_run` 落库。
- `cli.py run` 增加 `--scenario`，默认 `None`。
- 不改 §2 中任何函数签名。

### 8.3 check_p0 的验收口径

- 3 个 case：golden B2、golden B1、adversarial B4，scenario 统一 `S1`。
- 除 §4 的 7 项外，额外断言每个 run 至少 1 条 usage、latency > 0，且 reports 表能读回单次 token/latency。
- 允许 agent 本身失败（FAILED/REJECTED），但 run/span/log/usage 的链路必须完整；这验证“单 case 失败不中断批量”。
