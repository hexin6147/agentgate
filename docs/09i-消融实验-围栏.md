### 0.4 核心结论（30 秒版）

> 同一批对抗用例、同一套 Mock 工具，**只切围栏一个开关**：
> Sample A 对抗集 25 条里，无围栏时 **19 条真的执行了高危写操作**，通过率 6/25；有围栏时 **0 条**，25/25。
> Sample B 对抗集 8 条里，无围栏 **4 条执行了退款提交**，通过 1/8；有围栏 **0 条**，8/8。

## 1. 为什么要做消融

之前的报告能回答"Agent 表现如何"，回答不了"平台有没有用"。区别是：

| 问题 | 证据类型 | 之前有没有 |
|---|---|---|
| 这个 Agent 行为对不对？ | 能力证据（L1） | ✅ 有 |
| 去掉平台某个模块，会变差多少？ | 归因证据（L2） | ❌ 只有 BGE 一处 |
| 用了平台，业务指标改善多少？ | 效果证据（L3） | ❌ 无真实环境 |

L3 需要真实用户和线上流量，现在拿不到。但 **L2 可以现在做**，方法是消融：

> 同一批用例，只开/关一个模块，看指标差多少。
> 差值就是这个模块的贡献。

---

## 2. 方法

| 项 | 设置 |
|---|---|
| 用例 | `eval/dataset/adversarial`（25）、`eval/dataset/golden`（37）、`eval/dataset_ticket/adversarial`（8）、`eval/dataset_ticket/golden`（8） |
| Agent | 规则版（`build_agent("rule")` / `("ticket")`），不涉及 LLM |
| 工具 | 同一套 Mock，同一 fixture |
| 变量 | 只切 `fence_enabled`：`ToolRegistry(fence_enabled=False)` |
| 判定 | `score_case` 的标准 `passed`（行为 + 路由 + 无围栏违规 + trace 完整） |
| 高危写入 | `specs` 里 `risk == "high"` 的工具：`create_issue` / `request_review` / `update_ticket_status` / `submit_ticket` |

关掉围栏时，`check()` 返回空列表，`all_passed([]) == True`，所以每个工具调用都被视为允许——**这正是"没有平台管控"的样子**。

## 4. 解读

### 4.1 围栏的贡献是"阻断"，不是"提示"

关掉围栏后，Agent 的**决策没变**（照样把"直接发起变更评审"识别为 B4），变的只是"执行前有没有校验"。

> 这说明越权拦截靠的是**执行前的硬校验**，不是模型自觉，也不是事后日志。

### 4.2 阻断是单向的

| 数据集 | 有围栏 | 无围栏 | 差值 |
|---|---|---|---|
| A 对抗通过率 | 100% | 24% | **+76pp** |
| B 对抗通过率 | 100% | 12.5% | **+87.5pp** |
| 正常集通过率 | 100% | 100% | 0 |

**代价为 0**：45 条正常用例在两种模式下表现完全一致。

### 4.3 为什么 A 的 6/25 也能过

无围栏时仍有 6 条通过——是 B5（超边界）类，在路由阶段就被 `R4` 拒绝，根本没走到工具执行。

> 这也说明平台是**分层拦截**：路由层挡一部分，围栏层挡剩下的。两层缺一不可。

---

## 5. 局限（必须主动说）

| 局限 | 影响 |
|---|---|
| 只切了围栏一个模块 | 不能说明上下文、judge、Rubric 的贡献 |
| 正常集不含**合法写操作** | "无误伤"只说明这批用例没被误伤，不能外推 |
| Mock 工具 | 证明的是拦截逻辑生效，不是真实系统未被写 |
| 规则版 Agent | LLM 路径下的行为未验证 |
| 对抗集仅 33 条 | 不做统计推断，只做机制验证 |
| 阈值与配置未变 | 换一套围栏规则，差值会变 |

**最需要注意的是第二条**：真正衡量误伤要用 `false_block_rate`，它在 `09*` 里是 0%，但那也是在"没有合法写用例"的数据上算的。这是一个已知的评测集缺口（见 `21` §4）。

## 6. 复现

```bash

.venv/bin/python eval/scripts/ablation_fence.py

  --agent rule \
```
