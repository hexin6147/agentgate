## 3. 护栏与修复映射

| 失败类型 | 数量 | 护栏 | 规则 |
|---|---|---|---|
| 变更请求被判成 B3 | 2 | **写操作护栏** | 命中"提交/推上去/提上去/走流程"等，强制 B4（除非已是 B4/B5） |
| 模糊追问被判成 B2 | 2 | **模糊查询护栏** | 命中"怎么处理/那个问题/处理一下"等，返回 None → B6 |
| 汇总查询被判成 B3 | 3 | **汇总一致性护栏** | 命中"隐患/哪些点/事项"等且无决策词，降为 B2 |

> 设计原则：**LLM 负责语义理解，规则负责安全与一致性校正**。护栏只覆盖已知高风险模式，不追求替代模型。

---

## 5. 结论

1. **混合分类可用**：LLM 主分类 + 规则护栏，在 dev 上把 91.9% 提升到 100%；
2. **护栏是安全网，不是主力**：3 类护栏只覆盖 7 条已知失败模式；
3. **held-out 未回归**：20/20 保持；
4. **来源标注仍是短板**：dev 73.3%，held-out 66.7%；
5. **drift 仍是短板**：dev 23.9%，说明 BGE 筛选在部分同义查询上仍保留噪声。

---

## 6. 局限

| 局限 | 影响 |
|---|---|
| dev 是护栏调参集 | 86/86 是 in-sample，不是泛化 |
| held-out 仅 20 条 | 波动大 |
| held-out 曾被探针/LLM 验证使用 | 不是严格盲测 |
| 摘要未人工复核 | 质量只看样例 |
| 无 Sample B | 未验证跨范式 |

**诚实表述**：

> "dev 的 100% 是 in-sample：7 条失败是我用来设计护栏的。护栏让 held-out 没有回归，但要证明泛化，需要新的 held-out2。"
