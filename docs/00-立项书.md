## 0. 文档导读

### 0.1 这份文档的目的

回答一个问题：**这个项目值不值得投、投多少、边界在哪、什么情况下停。**

它**不**回答"问题到底怎么解、指标怎么定、竞品怎么做"——那些是 G1 和 G2 的内容。

### 0.2 读者与使用方式

| 读者 | 怎么用 |
|---|---|
| 项目负责人 | 做 Go / No-Go 决策，锁范围与资源 |
| 面试官 | 看立项逻辑是否成立：问题假设是否可信、取舍是否清楚 |
| G1–G7 | 引用本文的目标、范围、约束、决策，不重复论证 |

### 0.3 本文包含什么

```
§1 问题假设（1 页）        ← 谁痛、为什么现在
§2 立项决策                ← 投不投、备选方案、前置条件
§3 目标与范围              ← 做什么、不做什么
§4 资源、约束与依赖         ← 人、时间、钱

§6 里程碑与 Gate           ← 什么时候检查
§7 决策记录                ← 关键取舍
§8 结论与下一步
```

### 0.4 核心结论（30 秒版）

> **Go。** 用 8 周、约 96–100h、¥300 预算，做一个轻量的 Agent 运行沙箱与离线评测平台（AgentGate）；研发协作 Agent 作为 Sample A，售后工单 Agent 作为可选 Sample B；工具全部 Mock；不做多租户、线上流量、真实系统集成。

## 1. 问题假设（1 页）

> **性质**：这是**假设**，不是经过用户验证的结论。详细论证与证据边界见 `01-问题定义.md` §2–§3。

### 1.1 一句话假设

> 业务 Agent 从 Demo 走到生产，卡点集中在**管控、观测、回归、复用**四件事上，而不是"模型能力不够"；现有方案没有提供一套轻量、可接入、可观测、可回归的评测基础设施。

### 1.2 谁、什么场景、什么痛

| 项 | 假设内容 |
|---|---|
| 用户 | Agent 开发者 / 业务团队；评测 / 效能 / AI 平台团队；管理层 / 合规 |
| 场景 | Agent 上线前的离线仿真、行为评测、版本回归 |
| 核心痛点 | 人工试用不可复现；成品 SaaS 执行链路封闭；大厂平台重且定制成本高；自建脚本重复造轮子 |
| 现状替代 | Claude Tag / 豆包工作伙伴 / 火山 AgentKit / 美团评测平台 / 团队自建脚本 |

### 1.3 为什么现在

1. **平台化趋势**：火山 AgentKit、美团 Agent 评测平台、腾讯云 ADP、阿里云 Agent Sandbox、华为云 AgentArts、Pyra 都在建「运行治理 + 评测底座」；
2. **招聘信号**：46 份 AI PM JD 中，23 份提到 Agent，10 份要求评测能力；
3. **技术条件**：LangGraph 支持 interrupt / checkpointer / trace；function calling 稳定；LLM 成本可承受；
4. **成品缺口**：成品 SaaS 短期不会开放执行链路，第三方评测基础设施有空间。

### 1.4 待验证的核心假设

| 编号 | 假设 | 验证时点 |
|---|---|---|
| H1 | 统一 Adapter 能接入协作型与受限型两类 Agent | W7 |
| H2 | 平台能承载业务方自有用例与 Rubric，而不是内置万能用例 | W5–W6 |
| H3 | 权限围栏能被离线用例稳定验证 | W6 |

> 完整假设 H1–H8、验证方式与失效处理见 `01-问题定义.md` §8。

### 1.5 证据边界（诚实声明）

本项目没有真实企业用户访谈与线上流量。问题假设基于：公开产品能力、46 份 JD、公开行业实践、人工构造场景。它是一个**假设驱动的 POC**，不是经过大规模验证的结论。

## 2. 立项决策

### 2.1 结论：Go

### 2.2 为什么投（三条）

1. **方向成立**：平台化有明确市场验证，且与目标岗位（#24 评测平台、#37 AI 平台、#45 企业智能体、#13 Agent 平台）直接对齐；
2. **成本可控**：已有 A 方向资产可复用，平台层为轻量实现，不做多租户与完整 SaaS；
3. **风险可退**：Sample B 可砍、飞书可降级 Streamlit、LangGraph 可回退自研状态机、8 周可拉长到 9 周。

### 2.3 备选方案与取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| 保留单 Agent 应用 | ❌ | 面试官容易把它当应用 Demo，叙事有天花板 |
| 方案1 平台完整版 | ❌（本期） | 工作量过大，8 周不可控 |
| **方案1 平台轻量版** | ✅ | 平台叙事 + 个人可控成本 |
| 方案2 MCP Skill 市场 | ❌ | 生态产品逻辑复杂，超出 POC |
| 纯 B 方向工单 Agent | ❌ | 单点应用，平台岗适配弱 |

## 3. 项目目标与范围

### 3.1 一句话项目定义

> 一个轻量、可运行的 Agent 运行沙箱与离线评测平台：任何 Agent 通过统一 Adapter 接入后，可在仿真环境中执行；平台负责 trace、用例管理、行为断言、越权拦截、badcase 归因与版本回归。**平台统一基础设施，用例与判定标准由业务方提供。**

### 3.2 目标（OKR 摘要）

| 目标 | 成功标准 |
|---|---|
| O1 平台产品定义完整 | 16 份文档齐全、可追溯；每模块有"实现/简化/工业补齐" |
| O2 平台可运行 | 可注册 Sample A、跑通 golden、出 trace、出回归报告；飞书可 @ |
| O3 跨范式评测 | Sample A 必做；Sample B 可选；Rubric 可配置 ≥2 |
| O4 面试叙事成立 | 30 秒 / 3 分钟 / 5 分钟讲稿；20–30 道防守题 |

### 3.3 成功标准（摘要）

| 指标 | 目标 |
|---|---|
| Agent 接入耗时 | ≤ 30 分钟 |
| trace 完整率 | 100% |
| 回归自动化率 | 100% |
| 运行可复现率（Mock） | 100% |
| Rubric 可配置数 | ≥ 2 |

> 指标分类（硬门槛 / 基线相对 / 业务推导 / 工程约束 / 待校准）与详细口径见 `01-问题定义.md` §7。行为类百分比为初设值，G4 前必须校准。

### 3.4 In Scope

- 平台层：Agent 注册、用例管理（内容归业务方）、批量运行、trace 查看、回归对比、Rubric 配置（权重归业务方）
- 适配层：Agent Adapter、Tool Adapter
- 运行时：Harness、LangGraph 编排、上下文筛选、规则引擎
- 工具层：5 读 + 3 Mock 变更 + 2 交互 + 权限围栏
- Sample A：研发协作 Agent（飞书入口）
- Sample B：售后工单 Agent（可选，W7 决定）
- 演示：CLI / Streamlit + 飞书

### 3.5 Out of Scope

- 真实 Jira / GitLab / CI / 权限中心
- 真实变更动作
- 多租户、审批流、细粒度权限
- 可视化编排、Skill 市场
- 多模态、私有化、性能压测、SLA
- 模型训练
- **跨业务通用用例库 / 通用 golden 集**

### 3.6 项目不是什么（Non-goals）

| 不是 | 原因 |
|---|---|
| 一个 IM 协作 Agent 应用 | 那只是 Sample A |
| 多租户 SaaS 管理后台 | 个人 POC 成本边界 |
| 完整企业 Harness | 不做容器隔离、集群调度 |
| 评测豆包工作伙伴 / Claude Tag 本身 | 复刻范式、自建底座 |

## 5. 风险与降级

| # | 风险 | 应对 | 触发条件 |
|---|---|---|---|
| 1 | 平台层范围蔓延 | 能力锁 MVP 六项；不做 SaaS 后台 | 平台层超 10h |
| 2 | 飞书接入踩坑 | W2 spike；Streamlit 兜底 | spike 失败 |
| 3 | Sample B 拖累主线 | B 可选、W7 再定、≤4h | A 未跑通 |
| 4 | "这算平台吗"被质疑 | Adapter + 双示例 + 平台指标 | 面试追问 |
| 5 | 评测集质量不足 | 对抗 ≥30%；forbidden_behavior | golden 通过率 >95% |
| 6 | 行为指标主观 | 硬规则/人工分层；抽检 | 标注一致性低 |
| 7 | Mock 被质疑 | 定位为围栏逻辑与回归稳定性 | 面试追问 |

**降级顺序**：先砍 Sample B → 再砍 Streamlit 视图 → 最后才考虑缩减评测集（不可砍围栏与回归）。
