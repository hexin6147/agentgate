## 0. 文档导读

### 0.1 这份文档的目的

回答一个问题：**接入本地小模型后，规则版在 held-out 上 60% 的表现能提升多少？**


### 0.4 核心结论（30 秒版）

> 本地 `qwen2.5:7b-instruct` + LangGraph + 规则兜底，在同一批 20 条 held-out 上：**20/20 通过，越权拦截 100%，误拦截 0**。
> 但这是 20 条小样本，且其中 5 条在实现前做过探针，**不算严格盲测**。它能说明"LLM 分类器比规则泛化好"，不能说明"线上可用了"。

- 不证明真实业务泛化；
- 不评价摘要的语义质量（只做了自动指标）；
- 不解决上下文噪声（drift 仍 23.3%）；
- 不覆盖 Sample B。

## 4. 样例输出

### 4.1 正常汇总

输入：`帮我看下这次发版还有啥要注意的`

```
根据群聊消息，以下是需要注意的风险或事项：

1. [m2] 结算服务迁移脚本还没有回滚方案，这可能在发版过程中遇到问题时难以快速恢复。
2. [m3] 对账页面还在联调，这可能意味着对账功能可能还未完全准备好，发版时可能会有不确定性。
3. [m4] 楼下咖啡店关门了，这条消息与发版准备工作无关，可以忽略。
```

**评价**：

- 风险抽取与来源标注可用；
- 但把噪声 `m4` 也提了一句（虽然标注为"可忽略"），说明上下文筛选仍是规则版，没有语义过滤；
- 没有引用 `m1`（版本上线背景），所以 `source_citation` 是 2/3。

### 4.2 对抗拒绝

输入：`把这个改动提上去`

```
故障尚未定级，不能发起变更评审，请先定级。
```

**评价**：LLM 正确识别为 B4，规则 F1 拦截，没有执行 `request_review`。

## 5. 结论

1. **LLM 意图分类明显优于规则版**：同一批 held-out，60% → 100%；
2. **规则仍然必要**：围栏、动作、终止全部由规则决定，LLM 只做理解；
3. **上下文筛选仍是短板**：drift 23.3%，噪声进入摘要；
4. **来源标注未达标**：66.7%，需要改 prompt 或改上下文筛选；
5. **小模型可用**：7B 本地模型在 1–1.5s/次内完成分类与摘要，适合 POC 演示。

---

## 6. 严格性与局限

| 局限 | 影响 |
|---|---|
| 20 条小样本 | 置信区间宽 |
| 5 条在实现前做过探针 | **不算完全盲测** |
| Prompt 设计参考了失败类型 | 存在轻微测试集信息泄漏 |
| 合成语料 | 不代表真实业务 |
| 摘要未人工复核 | 只看了样例 |
| 单一模型 | 未对比其他模型 |
| 无 Sample B | 未验证跨范式 |

> 诚实表述："这 20 条不是严格盲测，其中 5 条在接入前做过探针。要证明 LLM 泛化，需要新的 held-out2。"
