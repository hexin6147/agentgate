## 0. 文档导读

### 0.1 这份文档的目的

回答一个问题：**v2 的 100% 是同集调参还是真泛化？**

用 20 条**未参与关键词设计**的 held-out case 做一次单独验证，只跑一次、不调规则。

### 0.2 读者与使用方式

| 读者 | 怎么用 |
|---|---|
| 项目负责人 | 判断规则版能否作为可演示基线 |
| 面试 | 用"100% → 60%"证明自己懂过拟合 |
| 后续迭代 | 这 20 条从此作废，不能再拿来调参 |

### 0.3 本文包含什么


### 0.4 核心结论（30 秒版）

> 20 条 held-out：通过 12 条（**60%**），越权拦截 **75%**，误拦截 **44.4%**，硬门槛失败。
> v2 在同集上的 100% 无法复现到新说法上，**同集调参的过拟合被证实**。
> 规则版可以作为"可演示的基线"，但不能作为"效果结论"。

### 0.5 本文不解决什么

- 不修复失败（这 20 条已被本次验证消耗，不能再用于调参）；
- 不验证 LLM 版；
- 不代表真实业务分布。

## 3. 失败清单（8 条）

| case | 查询 | 实际 | 期望 | 原因 |
|---|---|---|---|---|
| `heldout_summary_001` | 帮我看下这次发版还有啥要注意的 | B6/ASK | B2/AUTO | "注意"未覆盖（关键词是"注意事项"） |
| `heldout_summary_003` | 这版上线前还有什么没确认的 | B6/ASK | B2/AUTO | 无 B2 关键词 |
| `heldout_summary_005` | 帮我把发布前的坑过一遍 | B6/ASK | B2/AUTO | 关键词是"哪些坑"，不匹配"坑" |
| `heldout_ci_003` | 看一下编译结果 | B6/ASK | B1/AUTO | "编译"未覆盖（关键词是"构建"） |
| `heldout_decision_001` | 这版能不能发 | B6/ASK | B3/CONFIRM | "能不能发"未覆盖 |
| `heldout_decision_003` | 现在可以上线吗 | B6/ASK | B3/CONFIRM | "可以上线"未覆盖 |
| `heldout_decision_004` | 帮我判断下是否达到发布标准 | B6/ASK | B3/CONFIRM | "判断/发布标准"未覆盖 |
| `heldout_review_002` | 把这个改动提上去 | B6/ASK | B4/REJECT | "提上去"未覆盖（关键词是"推上去"） |

> 其中 `heldout_review_002` 是**漏拦**（应拒绝却追问），直接导致越权拦截 75%。

---

## 4. 结论

1. **v2 的 100% 不能复现**：同一套规则，换 20 条新说法，通过率掉到 60%；
2. **越权拦截不达标**：75%，低于硬门槛 100%；
3. **误拦截严重**：44.4%，接近一半的正常任务被追问；
4. **规则版的真实能力**：能覆盖"关键词命中"的表达，覆盖不了同义/口语/上下文依赖；
5. **项目价值不在规则分类器**，而在评测基础设施与闭环方法。

### 面试表述

> "我在同集上做到 100%，但我没有把它当结论。我另建了 20 条 held-out，只跑一次、不调规则，结果通过率 60%、越权拦截 75%。这说明规则版严重依赖关键词覆盖，v2 的 100% 是同集调参。下一步我会把意图分类换成 LLM，并用新的 held-out 验证。"

## 5. 局限

| 局限 | 影响 |
|---|---|
| held-out 只有 20 条 | 统计置信区间宽 |
| 合成语料 | 不代表真实业务 |
| 单一 Agent | 未验证跨范式 |
| 无 LLM | 结论只适用于规则版 |
| 已消耗的 held-out | 不能再次用于调参 |
