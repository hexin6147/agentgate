### 0.4 核心结论（30 秒版）

> 把意图分类器从"LCS + 少量示例"改成"显式短语/关键词 + 最长匹配"，并补齐 6 类行为的关键词表。
> 结果：86 条用例从 59 通过（68.6%）提升到 86 通过（100%），越权拦截从 80% 提升到 100%，误拦截从 32.4% 降到 0。
> **但这 100% 是"同集调参"的结果**：关键词是从这 27 条失败里总结出来的，再用同一批 case 回归，不能证明泛化。
> **held-out 实测：20 条只通过 12 条（60%），越权拦截 75%**——泛化不足已被证实。详见 `09b-评测报告-heldout.md`。

- 不接入 LLM；
- 不解决上下文筛选质量（drift 仍 24.3%）；

## 2. 改动内容

### 2.1 分类器

| 改动 | 之前 | 之后 |
|---|---|---|
| 匹配方式 | LCS（最长公共子串） | **显式短语包含** |
| 短语来源 | 仅 examples | **examples + keywords** |
| 多命中 | 按风险优先 | **最长短语优先**，同长才按行为优先级 |
| 无命中 | 可能被通用词误匹配 | **默认 B6** |
| 通用词 | "一下"可触发 B2 | "一下"不在任何关键词表 |

### 2.2 关键词表

| 行为 | 关键词 |
|---|---|
| B1 CI | `CI`、`构建`、`流水线`、`打包` |
| B2 汇总 | `汇总`、`梳理`、`整理`、`风险`、`隐患`、`注意事项`、`关注点`、`哪些点`、`需要盯`、`事项`、`列出来`、`哪些坑` |
| B3 决策 | `能不能上线`、`上线结论`、`是否可以上线`、`定级`、`结论` |
| B4 变更 | `评审`、`变更`、`走流程`、`走个流程`、`推上去`、`提交` |
| B5 超边界 | `直接上线`、`直接放行`、`批准`、`赔付`、`批一下`、`帮我发布` |
| B6 信息不足 | 无关键词，兜底 |

### 2.3 指标口径

| 指标 | 调整 |

| source_citation | 只对 B2 计算；B1 查询不要求引用来源 |

## 6. 过拟合风险（必须主动讲）

> **这 100% 不能当作"问题解决了"。**

原因：

1. 关键词是从 v1 的 27 条失败里总结出来的；
2. 回归用的还是同一批 86 条 case；
3. 没有任何 held-out 集；
4. 规则版没有语义理解，换一种说法仍可能失败。

**正确表述**：

> "我在同一批用例上完成了发现→修复→回归的闭环，指标从 68.6% 提升到 100%，27 条修复、0 条新增失败。但我清楚这是同集调参，100% 不代表泛化。下一步我会留出 held-out 集，或者把分类器换成 LLM，再验证一次。"

**如果面试官追问**：

- "你是不是针对测试集调规则？" → 是，这一轮是；所以我把它定位为"闭环验证"，不是"效果结论"。
- "真实场景能到 100% 吗？" → 不能保证；规则版的同义词覆盖永远有长尾。
- "那这个项目还有什么价值？" → 价值在评测底座和闭环方法，不在于这个规则分类器。
