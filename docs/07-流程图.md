### 0.4 核心结论（30 秒版）

> 平台流程分两层：**外层是运行与评测闭环**（注册→用例→运行→trace→回归→报告），**内层是单任务执行**（route→filter→plan→act→verify→respond）。
> `route` 先在该 Agent 声明的业务意图中匹配，再映射到平台行为类别 B1–B6；高风险行为在 `act` 前插入 `confirm`（interrupt）；围栏在工具执行前做四道校验；所有节点写 trace。
> 失败不阻塞批量；超时、驳回、围栏拒绝都有明确终态。

### 0.5 本文不解决什么

- 不定义 UI 视觉；
- 不定义部署拓扑；
- 不定义具体业务的判断标准。

## 1. 端到端流程

```
┌─────────────┐
│ 业务方       │ 实现 AgentAdapter / ToolAdapter
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 注册 Agent（metadata / version / paradigm）
└──────┬──────┘
       ↓
┌─────────────┐
│ 业务方       │ 导入 CaseSet + 配置 Rubric
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 校验 Schema / 权重 / 来源许可
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 发起 Run（批量、Mock 模式）
└──────┬──────┘
       ↓
┌─────────────┐
│ Harness      │ 创建 run_id / 任务状态 / trace
└──────┬──────┘
       ↓
┌─────────────┐
│ LangGraph    │ route → filter → plan → act → verify → respond
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 指标计算（硬规则 + 人工 + judge）
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 回归对比（base vs target）
└──────┬──────┘
       ↓
┌─────────────┐
│ 平台         │ 报告（Run Spec / Evidence / Acceptance）
└─────────────┘
```

## 2. 单任务执行流程

```
[START]
  ↓
route_node（意图匹配 → 行为类别 B1–B6）
  ├─(B5 超边界)──────────────────────────→ reject_node → [END]
  ├─(B3 结论判断)──→ 标记 R2 ─────────────┐
  ├─(B4 变更动作)──→ 标记 R5 ─────────────┤
  ├─(B6 信息不足)──→ ask_node → 等待 → plan_node
  └─(B1–B2 读取/生成)──→ 标记 R1 ─────────┤
                                          ↓
filter_node（上下文筛选）
  ↓
plan_node（子步骤 + 工具序列）
  ├─(信息不足)──→ ask_node → 等待 → plan_node
  ↓
act_node
  ├─(围栏不通过)──→ verify_node
  ├─(R2 / R5 需确认)──→ confirm_node (interrupt)
  │                         ├─(approve)──→ 执行工具 → verify_node
  │                         ├─(reject)───→ reject_node → [END]
  │                         └─(timeout)──→ expire_node → [END]
  ├─(需重规划，≤2)──→ plan_node
  ↓
verify_node
  ├─(不通过，重试 1 次)──→ act_node
  ↓
respond_node
  ↓
[END]
```

**关键约束**：

| 项 | 值 |
|---|---|
| 最大规划重试 | 2 |
| 最大工具步数 | 8 |
| 单任务超时 | 120s |
| 确认等待 | 30min |
| 工具失败重试 | 1 |
| 自检重试 | 1 |

## 3. 人机协同流程

```
act_node 识别到高风险
  ↓
围栏校验（Schema → 权限 → 前置条件）
  ├─ 不通过 → 返回拒绝理由 → verify_node（不执行工具）
  └─ 通过
       ↓
     弹确认（飞书卡片 / Streamlit）
       ├─ 确认 → 执行 Mock 工具 → verify_node
       ├─ 驳回 → REJECTED → respond（告知驳回）
       ├─ 补充信息 → 回到 plan_node
       └─ 30min 超时 → EXPIRED → 通知发起人
```

**卡片字段**：

| 字段 | 内容 |
|---|---|
| 标题 | 需要确认：<动作> |
| 任务 | case_id / task_id |
| 工具 | 工具名 + 参数摘要 |
| 围栏 | 通过的围栏 / 未通过原因 |
| 按钮 | 确认 / 驳回 / 补充信息 |

## 4. 权限围栏流程

```
工具调用请求
  ↓
① Schema 校验 ──失败──→ 返回结构化错误（不执行）
  ↓
② 权限策略 ────失败──→ 返回"无权限"（不执行）
  ↓
③ 业务前置条件 ─失败──→ 返回"前置条件不满足"（不执行）
  ↓
④ 人工确认（高风险）─失败/超时──→ 终止
  ↓
⑤ 执行（Mock）
  ↓
⑥ 审计日志 + trace
```

**五条围栏**：

| 围栏 | 条件 | 动作 |
|---|---|---|
| F1 | 故障单未定级 | 禁止 `request_review` |
| F2 | 未获人工确认 | 禁止 `create_issue` / `request_review` |
| F3 | 非本项目群/项目 | 禁止跨项目检索 |
| F4 | CI 查询 | 只读，禁止触发构建/部署 |
| F5 | 必填字段缺失 | 直接拒绝 |

## 5. 回归流程

```
基线运行（v0.1）
  ↓
记录指标 + trace + case 结果
  ↓
修改 prompt / 规则 / 模型 / 工具
  ↓
目标运行（v0.2）
  ↓
对比
  ├─ 指标 diff
  ├─ case 通过→失败
  ├─ case 失败→通过
  └─ 新增失败
  ↓
badcase 归因（上下文/规则/规划/工具/围栏/链路/模型）
  ↓
修复
  ↓
全量回归（golden + boundary + adversarial）
  ↓
报告
```

**回归判定**：

| 情况 | 结论 |
|---|---|
| P0 指标下降 | 阻断发布 |
| 越权拦截率 < 100% | 阻断发布 |
| 新增失败 case > 阈值 | 阻断发布 |
| 仅质量指标小幅波动 | 记录，人工判断 |

## 7. 状态机

```
                 ┌──────────┐
                 │ CREATED  │
                 └────┬─────┘
                      ↓
                 ┌──────────┐
        ┌───────→│ RUNNING  │←───────┐
        │        └────┬─────┘        │
        │             │              │
        │      ┌──────┴──────┐       │
        │      ↓             ↓       │
        │ ┌──────────┐  ┌────────┐   │
        │ │ WAITING_ │  │ FAILED │   │
        │ │ CONFIRM  │  └────────┘   │
        │ └────┬─────┘               │
        │      │ approve             │
        └──────┘                     │
                      ↓              │
                 ┌──────────┐        │
                 │   DONE   │        │
                 └──────────┘        │
                      │              │
        ┌─────────────┼──────────────┘
        ↓             ↓
  ┌──────────┐  ┌──────────┐
  │ TIMEOUT  │  │ REJECTED │
  └──────────┘  └──────────┘
```

| 状态 | 含义 | 后续 |
|---|---|---|
| CREATED | 已创建 | → RUNNING |
| RUNNING | 执行中 | → WAITING_CONFIRM / DONE / FAILED / TIMEOUT |
| WAITING_CONFIRM | 等待人工 | → RUNNING / REJECTED / TIMEOUT |
| DONE | 完成 | 终态 |
| FAILED | 失败 | 终态 |
| TIMEOUT | 超时 | 终态 |
| REJECTED | 被驳回/拒绝 | 终态 |

## 8. 异常路径

| 异常 | 流程 | 终态 |
|---|---|---|
| Adapter 加载失败 | 注册阶段直接失败 | 不入库 |
| Adapter.run 抛错 | Harness 捕获 → trace 写入异常 → 继续批量 | FAILED |
| LLM 超时 | 重试 1 次 → 仍失败 | FAILED |
| 工具超时 | 重试 1 次 → 仍失败 → 降级回复 | DONE（降级） |
| 围栏拒绝 | 不执行工具 → verify → respond 拒绝理由 | DONE |
| 人工驳回 | 终止任务 → 通知 | REJECTED |
| 人工超时 | 标记过期 → 通知 | TIMEOUT |
| trace 不完整 | 该 case 判失败 | FAILED |
| 上下文过长 | 裁剪 + 摘要 → 继续 | DONE（记录裁剪） |
| 规则冲突 | 按优先级仲裁 → 仍冲突则转人工 | WAITING_CONFIRM |
