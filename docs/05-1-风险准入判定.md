### 0.4 核心结论（30 秒版）

> 判定看六个维度：**是否变更数据/系统、是否对外输出、是否接触敏感数据、影响范围、可逆性、链路长度**。

## 1. 为什么需要准入判定

不是所有 Agent 都需要重型评测。

- 只做摘要、检索、草稿，人最终审核，不触发任何变更 → 低风险，人工试用即可；
- 能调用工具、修改工单、发起评审、对外输出 → 高风险，必须评测、围栏、审计。

**准入判定的作用**：把"要不要做评测"从主观争论变成可解释的规则，避免两种错误：

1. 低风险 Agent 被过度评测，浪费资源；
2. 高风险 Agent 没做评测就上线，造成事故。

---

## 2. 判定维度

| 维度 | 取值 | 说明 |
|---|---|---|
| D1 数据/系统变更 | 无 / 只读 / 写入 | 是否修改业务数据或触发系统动作 |
| D2 对外输出 | 内部草稿 / 对内发布 / 对外发布 | 输出是否会被外部看到 |
| D3 敏感数据 | 无 / 内部 / 敏感 | 是否接触个人信息、财务、权限数据 |
| D4 影响范围 | 单人 / 单团队 / 多团队 / 全公司 | 出错时影响多少人 |
| D5 可逆性 | 可撤销 / 难撤销 / 不可逆 | 出错后能否回滚 |
| D6 链路长度 | 单步 / 多步 | 是否多工具串联、长任务 |

---

## 3. 风险等级 L0–L3

| 等级 | 特征 | 典型场景 | 评测要求 |
|---|---|---|---|
| **L0** | 只读、内部、可逆、单步 | 查文档、搜群消息 | 人工试用 |
| **L1** | 只读 + 生成草稿，人审核 | 摘要、风险罗列 | 轻量评测（抽检） |
| **L2** | 工具调用、内部写入、多步 | 创建 Issue、发起评审、改工单状态 | **强制评测 + 围栏 + 人工确认** |
| **L3** | 对外发布、敏感数据、不可逆、多团队 | 对外通知、资金、生产发布 | **强制评测 + 安全专项 + 审批 + 审计** |

### 3.1 判定规则

```
只要满足以下任一条件 → 至少 L2：
- 有写入类工具调用
- 有对外发布
- 多步链路 + 工具串联
- 接触敏感数据

满足以下任一条件 → L3：
- 不可逆动作（发布、资金、审批）
- 多团队/全公司影响
- 对外发布 + 敏感数据
```

## 4. V1 / V2 判定

| 版本 | 能力 | 等级 | 是否需要评测底座 |
|---|---|---|---|
| V1 只读 | 读群、查文档、生成摘要 | L0/L1 | ❌ |
| **V2（本项目）** | V1 + Mock 变更工具 + 多步链路 | **L2** | ✅ |

> Sample A（研发协作）与 Sample B（售后工单）都属于 V2：
> - Sample A：可调用 `create_issue`、`request_review`、`update_ticket_status`；
> - Sample B：可提交工单、改状态、触发赔付流程（Mock）。
> 因此两者都必须走平台评测。
>
> **注意**：L2/L3 的判定依据是**行为类别**（B3 结论 / B4 写入 / B5 超边界），不是业务任务名称。不同业务的任务名不同，但行为语义一致。

## 5. 工具风险分级

| 工具 | 风险 | 等级 | 是否需要确认 | 围栏 |
|---|---|---|---|---|
| `search_chat_history` | 低 | L0 | 否 | 本群/时间窗 |
| `get_related_docs` | 低 | L0 | 否 | 项目权限 |
| `read_fault_logs` | 低 | L0 | 否 | 本服务/项目 |
| `query_ci` | 低 | L0 | 否 | 只读 |
| `fetch_code_docs` | 低 | L0 | 否 | 项目权限 |
| `reply_message` | 中 | L1 | 视规则 | 输出审核 |
| `ask_human` | 低 | L0 | 否 | — |
| `create_issue` | 高 | L2 | **是** | 项目成员、非重复、字段完整 |
| `request_review` | 高 | L2 | **是** | 故障已定级、变更单完整 |
| `update_ticket_status` | 高 | L2 | **是** | 状态机允许的迁移 |

## 6. 人机协同触发条件

以下任一条件触发人工确认或转人工：

| 条件 | 动作 |
|---|---|
| 调用 L2/L3 工具 | 人工确认 |
| 行为类别为 B3（结论/定级） | 人工确认 |
| 行为类别为 B4（写入/变更） | 围栏 + 人工确认 |
| 行为类别为 B5（超边界） | 拒绝并移交 |
| 上下文不足 | 主动追问 |
| 超出能力边界（真实审批/资金/发布） | 拒绝并移交 |
| 连续失败 2 次 | 转人工 |
| 人工确认超时 30min | 标记过期 |
| 用户明确要求人工 | 立即转人工 |

> 规则表细节见 `06-人机协同规则.md`。

## 9. 面试话术

> "我不是给所有 Agent 都套一套重型评测。我先用准入判定表看六个维度：有没有写入、有没有对外输出、有没有敏感数据、影响范围、可逆性、链路长度。
> 只读摘要落在 L0/L1，人工试用即可；一旦能调用变更类工具、进入多步链路，就落到 L2，必须做评测、围栏、人工确认和审计。
> 我的 Sample A 和 Sample B 都属于 L2，所以这个评测底座才有存在必要。"
