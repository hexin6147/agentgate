# 30 · DevMate 开发计划（执行版 v4）

> **定位**：9 工具 × 4 场景的研发协作 Agent；**故障排查是唯一 Agent 主场景**。
> **v4 改动**：删掉能力清单，改用「场景 × 技术点 × 验收 × Phase」范围矩阵。
> 日期：2026-11-20

---

## 0. 深度定义

一个技术点算“做到深度”，五条全满足：

| # | 条件 | 反例 |
|---|---|---|
| 1 | 有边界处理：空/超时/错误/超长/重复 | 只跑 happy path |
| 2 | 有量化：至少一个指标 | “能跑” |
| 3 | 有取舍说明 | 照抄默认配置 |
| 4 | 有测试：边界进测试 | 手工试一次 |
| 5 | 可从 trace 还原 | 只有最终输出 |

## 3. 深度门槛

| 技术点 | 浅做法（禁止） | 深做法（必须） | 证明 |
|---|---|---|---|
| Agent 循环 | 固定 3 步 | 路径随证据变、停止条件、循环检测、失败重规划 | 10 题 ≥2 种工具序列；重复调用能停 |
| 工具系统 | 返回 fixture | schema、超时、重试、并行、截断、错误分类 | 五类边界各有用例 |
| RAG | top-k 拼接 | hybrid + rerank + 引用 + 无结果兜底 | hit@5 ≥85%；引用 ≥95%；消融 |
| 上下文 | 全量拼接 | 预算、压缩、按优先级截断 | 200 行日志不爆；20 轮不丢关键 |
| 记忆 | 存聊天 | 写/读策略、跨场景、去重/过期 | 变更引用故障；过期不误导 |
| Prompt | 单模板 | 版本化、结构化输出、护栏 | 输出过 schema；非法有兜底 |
| MCP / FC | 只做一种 | 2 MCP + 2 FC；schema 对齐 | 两种都能跑，错误码一致 |
| 运行与观测 | print | 消费 AgentGate A0：span、token、latency | 每步可还原 |

## 4. 指标与闭环

### 4.1 北极星

| 层 | 指标 | 定义 | 初始目标 |
|---|---|---|---|
| 生产 | **周均被采纳结论数** | 活跃用户 × 人均周使用 × 采纳率 | 无用户，待定 |
| POC 代理 | **质量加权成功率** | 任务成功率 × 证据完整率 | ≥75% |
| 场景 | 根因命中 / 回归覆盖 / gap 召回 / SOP 完整 | 见 §1 矩阵 | 80/85/80/85% |
| 护栏 | 错误结论率 | 错误结论 / 总结论 | ≤5% |
| 护栏 | 引用准确率 | 出处支持结论 / 总引用 | ≥95% |

**“被采纳”的信号**：故障结论进复盘、回归清单被测试采用、gap 被补进需求、SOP 被照着做。

> POC 没有真实用户，北极星只能看代理；报告里必须写“代理指标，非生产”。

### 4.2 步长与鲁棒性

| 概念 | 定义 |
|---|---|
| 迭代步数 | plan → act → observe 算一步 |
| 工具调用数 | 一次迭代可调 1–N 个工具 |
| 有效步 | 新增证据或改变假设 |
| 冗余步 | 重复同工具同参数、查不相关内容 |

| 场景 | 迭代步数 | 工具调用 | 有效步占比 |
|---|---|---|---|
| 故障排查 | 4–8（上限 12） | 3–6 | ≥70% |
| 转测范围 | 3–5 | 3–5 | ≥80% |
| 需求澄清 | 3–5 | 3–5 | ≥80% |
| 新人上手 | 2–4 | 2–3 | ≥80% |

| 鲁棒性指标 | 定义 | 目标 |
|---|---|---|
| 工具成功率 | 成功 / 总调用 | ≥95% |
| 重试成功率 | 重试后成功 / 重试次数 | ≥80% |
| 降级率 | 走降级 / 工具失败 | ≤20% |
| 恢复率 | 失败后仍完成 | ≥70% |
| 循环率 | 重复调用被检测并停止 | 100% |
| 幻觉工具率 | 调用不存在的工具 | 0 |

### 4.3 Token 效率

| 指标 | 定义 | 初始目标 |
|---|---|---|
| 单任务 Token | 一次任务总 token | 故障 ≤20k；其余 ≤12k |
| 单有效结论 Token | 总 token / 有效结论 | 做趋势 |
| 上下文利用率 | 实际用到 / 窗口上限 | ≤90% |
| 截断率 | 触发截断的任务占比 | 记录，不设上限 |
| 单任务成本 | token × 单价 | 做趋势 |

**效率前沿**：多查一步可能多一条证据，也可能多 2k token。记录“步数–证据–token”三元组，找拐点，不搞一刀切限流。

### 4.4 数据闭环

```
badcase（评测失败 / 用户反馈）
  → 归因（检索/工具/规划/生成/证据）
  → 新评测用例
  → 修复
  → 回归
  → 复发监测
```

| 指标 | 定义 | 目标 |
|---|---|---|
| 闭环率 | 已修复 / 总 badcase | ≥80% |
| 回归覆盖 | 修复项进入回归 / 修复项 | 100% |
| 复发率 | 同类问题再次出现 / 已修复 | ≤5% |
| 用例增长 | 每轮新增用例 | 记录 |

> 规矩：每条 badcase 必须追到一条新用例；每条用例必须能追到来源。

### 4.5 沙箱 / 自主执行 / 评估闭环

| 能力 | 现在需要吗 | 什么时候需要 | 代价 |
|---|---|---|---|
| **评估闭环** | **必须** | 现在 | 已有 AgentGate |
| **沙箱** | **不需要** | 加写入/执行工具时 | 隔离环境 + 权限 |
| **自主执行** | **不需要** | P3 数字员工 | 沙箱 + 二次确认 + 审计 |

**为什么现在不需要沙箱**：9 个工具全是只读（指标/日志/发布/issue/文档/负责人/diff/用例/群聊），没有副作用；Mock 数据本身就是沙箱。

**什么时候需要**：

| 触发 | 需要补 |
|---|---|
| 建 issue / 提 MR | 沙箱 + 权限 |
| 触发回滚 / 发布 | 沙箱 + 二次确认 + 审计 |
| 发飞书消息 | 权限 + 内容审核 |
| 改配置 / 改代码 | 沙箱 + diff 审批 |

**接口预留**（P0 就加，值先填默认）：

```
side_effect: none | write | external
requires_confirmation: bool
```

现在全是 `none/false`；P3 加写工具时复用 AgentGate 的围栏与确认。

## 11. 可选轨道：Sandbox Runner（不阻塞）

> **不一定做**；不影响 P1–P3。触发条件：目标岗明确看重“沙箱跑 coding agent（Claude Code / DSH）”的实战。

### 11.1 关系

- 容器隔离跑在 **AgentGate 侧**（见 `29` §9）；
- DevMate 通过一个**可选工具** `run_coding_agent` 调用；
- 只有触发时才加这个第 10 个工具，并写 §8 变更记录。

### 11.2 最小方案

| 项 | 做法 |
|---|---|
| 任务 | 给一个失败单测，让 Claude Code / DSH 修 |
| 输入 | repo 快照 + 测试命令 |
| 输出 | diff + 测试结果 + 命令日志 |
| DevMate 角色 | 分发任务、收集结果、交给 AgentGate 评测 |
| 评测 | 测试通过、diff 未越界、无联网尝试 |

### 11.3 DoD

- [ ] 容器断网跑通；
- [ ] 编码 agent 完成 1 个任务；
- [ ] DevMate 能拿到 diff + 测试结果；
- [ ] 生成评测报告；
- [ ] 作为可选工具，不影响 9 工具主链。

### 11.4 不做

- 不做多语言、并行、生产级隔离；
- 不接真实仓库；
- 不与四个业务场景合并。
